# Threat model (initial)

Assets: Page publishing ability (Meta token), provider API keys and budget, owner credentials, content integrity (what gets published), the Page's reputation. Actors: remote attacker, malicious/compromised content source, malicious uploader (incl. a compromised owner device), buggy or manipulated LLM output, insider mistakes (owner), supply-chain compromise.

| ID | Threat | Mitigation (required) | Test |
|---|---|---|---|
| T-1 | **Indirect prompt injection**: article text, user-submitted topics, RSS fields or text inside images tell the LLM to ignore rules, change the answer, fabricate sources or approve itself | Treat all source text as untrusted data in clearly delimited fields; LLM calls have **no tools and no side effects**; output is schema-validated; policy decisions are made by backend code, never by LLM output; reviewer prompts never receive owner/system secrets; quote/number/url claims in output must appear in supplied evidence (string-match check) or be flagged; the safety review runs in a fresh context from the same evidence | Corpus of injection samples must not change decision, lane, answer or approval |
| T-2 | **SSRF / unsafe fetching** when fetching source URLs, RSS, images | Fetch only from registered domains; resolve DNS and block private/loopback/link-local/metadata IPs, re-check after redirects, limit redirects/size/time, no cookies/credentials, allowed content types | Unit tests with private IPs and redirect-to-private |
| T-3 | **XSS / CSRF in the web admin** (source text, captions and filenames are attacker-influenced) | Escape all rendered text, strict CSP, no inline scripts, SameSite cookies or bearer tokens held in memory, CSRF token on state-changing requests, `X-Frame-Options`/frame-ancestors, no secrets in URLs | Header tests; XSS payload fixtures render inert |
| T-4 | **Credential theft / brute force** | argon2id, login rate limit and lockout with audit, optional TOTP, rotating one-time refresh tokens stored hashed per device, revocation, private network access (Tailscale), TLS | Auth tests, replay of used refresh token revokes the family |
| T-5 | **Owner bootstrap and recovery** (who creates the first account, what if the password is lost) | First owner created by a one-time CLI command on the server (no public signup route); recovery only through server access (CLI reset) with audit; documented in `docs/operations.md` | CLI test; assert no registration route exists |
| T-6 | **Secrets leakage** (tokens in logs, error messages, prompts, backups) | Central redaction filter (Authorization, cookies, `access_token`, `OAuth` header, API keys, signed URLs), never store tokens in DB plaintext (encrypt with key from secret store or keep in secret store only), exclude `.env` from backups, secret scanning in CI | Log-scan test; gitleaks (or equivalent) in CI |
| T-7 | **Malicious upload** (polyglot, decompression bomb, huge dimensions, EXIF/metadata leakage) | Sniff by content, decode with Pillow under pixel/size limits (`MAX_IMAGE_PIXELS`), re-encode (strip metadata) before storage, random storage keys, no direct serving of uploaded bytes from the app origin | Fixtures: bomb, wrong extension, truncated |
| T-8 | **Supply-chain compromise** (PyPI/npm, base images) | Pin dependencies with hashes (lock file), minimal base image, `pip-audit`/image scan in CI, no `curl | sh`, ffmpeg from a trusted package source with version recorded | CI job |
| T-9 | **Check-then-act race** around publishing (kill switch toggled or content edited between gate and FINISH; two workers publish the same intent) | Gate facts are read from rows locked in one DB transaction (`SELECT ... FOR UPDATE` on the publishing record); `PUBLISHING` + `video_id` are committed before FINISH; unique non-terminal publishing record per revision; scheduler uses lease/`SKIP LOCKED`. **Residual window**: a kill switch flipped after the gate but before FINISH returns cannot stop that one request - accepted risk, mitigated by retraction (`docs/operations.md`) | Concurrency test with two workers; kill switch flip test |
| T-10 | **Model drift / bad output** (hallucinated sources, wrong rebus syllables, unsafe caption) | Schema validation, evidence string-match, human verification of rebus answers, QA hard failures, pilot human approval for every post | Golden evaluation set re-run when prompts/models change (`prompt_versions`) |
| T-11 | **Provider outage / cost runaway** | Timeouts, bounded retries with jitter, circuit breaker per provider, budget caps in `cost_ledger`, max tokens per call, cost recorded before retry | Fake provider fault tests |
| T-12 | **Data exposure via media serving** | Private bucket; short-lived signed URLs for the admin UI; the answer never appears in any publicly reachable object (reveal assets stored separately) | Access-control test on object keys |
| T-13 | **Insider error** (owner approves wrong revision, enables kill switch off by mistake) | Approval shows the exact content hash/preview; kill switch change requires re-authentication and is audited; dry-run mode for publishing in non-production | UI/E2E checks |

## Principle summary
The LLM is an untrusted advisor. External text is untrusted data. The backend policy plus a human are the only authorities. Anything irreversible (publishing) passes through one audited code path.
